# Agent Orchestrator GUIs: What Users Love and Hate (research as of 2026-11-25)

Scope: T3 Code, Conductor, OpenAI Codex app, Claude Code desktop, Opcode/Claudia, Crystal/Nimbalyst, Vibe Kanban, Superset, Sculptor, Cursor Agents Window, Zed agent panel, Warp, Jules, plus Emdash, FleetCode, Omnara, Antigravity, Juggler.

How I gathered it: HN threads (read directly), GitHub issue trackers (sorted by reactions/comments via the GitHub API, so the reaction counts below show demand), the OpenAI and Cursor community forums, and blog reviews. I could not fetch Reddit directly. Reddit sentiment comes in only where a review quotes it. Vendor-written comparisons (Nimbalyst, Conductor's compare pages) are marked as biased.

Notation: `NNNr` = GitHub reactions on the issue, `NNc` = comments.

---

## 1. Per-tool findings

### T3 Code (pingdotgg/t3code): Electron + local server + web/mobile clients, multi-provider
**Praised**
- Responsive UI. Better Stack: "noticeably responsive", project switching and long threads "feel instant" (one author, not benchmarked). A Reddit user quoted by andrew.ooo calls it "more polished and less bloated" than rival GUIs. https://betterstack.com/community/guides/ai/t3-code/ , https://andrew.ooo/posts/t3-code-review-open-source-agent-control-surface/
- One thread UI across many agents (Codex, Claude, Cursor, OpenCode, Pi, Grok, Antigravity...). Switching agent is a model-picker change.
- Remote control from phone/browser via T3 Connect / LAN / Tailscale / SSH without port forwarding. Reviewers see this as the main differentiator.
- Per-turn diff pane (unified/split), one-click "Commit, Push & Create PR", worktrees, cross-provider usage/cost view, project-less scratch threads, MCP endpoint for other agents to read threads.
- Free, MIT, BYO subscriptions.

**Complaints**
- **Storage/DB bloat from event sourcing.** This is the most striking finding in the tracker. 26.5 GB state DB with 2-22 s thread queries and ~137 s startup (#22659, #23000). Streaming reasoning snapshots stored as permanent events: 2.2 GB/day on OpenCode (#23365). Claude `Read` images inlined as base64: 1.4 GB, 46% of DB in a week (#26591). Workflow agent arrays re-stored on every update: 1.4 GB (#27598). Thread switches take 12-50 s when history-wide reads saturate the single SQLite reader (#24895). ~66 ms server CPU per stored event (#37877). "Deleting a thread says it permanently clears its history, but V2 keeps every event" (#17845). https://github.com/pingdotgg/t3code/issues/22659
- **Git process storms on Windows.** Every diff scroll runs 6 git commands per file, about 1,650 git processes to view 272 files (#40182). 15-17 git processes per open thread every 30 s poll (#40051). Checkpoint capture hits a 30 s git timeout in large repos and leaks temp dirs (#26227).
- **Wrapper overhead vs native agent.** "Usage is ~3x-5x higher than the native Claude app" (#7338, 21r/81c). "T3 Code is significantly slower than Codex for the same coding task (20+ min vs ~3m24s)" (#695, 32r). The FAQ admits that Agent SDK usage drains Claude 5-hour limits faster.
- Input lag 2-3 s in the composer, and settings take seconds to open (#440). A thread opens blank when the newest item is a large checkpoint (#28045). Resumed threads sit in "Working" for 9 min after an update (#25962). Context gets lost when the app is left idle (#2256).
- Telemetry on by default despite earlier promises (#4123, 46r: "Why promise no opt-out telemetry while telemetry has been on the whole time?"). New threads default to **Full access** (andrew.ooo). Worktrees eat disk: one user reclaimed 500 GB.
- UI regressions: the context-window indicator was hidden by default with no notice (#9352, 45r). Manual project order broke when the legacy sidebar was removed (#27062). New threads don't keep the last-used model/mode (#6508).

**Most-requested (by reactions)**: Pi provider (#402, 198r), Copilot CLI (#193, 185r), WSL (#192, 145r), OpenCode (#539, 130r), Steer/Queue follow-up modes (#231, 77r), notifications for completion/approval (#780, 64r), managing Cursor/Codex/Claude cloud sessions (#15644, 47r), slash commands (#2491), subagents as nested threads (#538), usage/quota visibility (#228), conversation branching (#1404), multi-repo projects (#1453), ACP adapter layer (#315).

### OpenAI Codex app (Electron; macOS Feb 2026, Windows Mar 2026, Linux preview Aug 2026)
**Praised**
- Diff panel. Every calls it "a standout feature" that they "haven't seen implemented cleanly elsewhere". https://every.to/vibe-check/codex-vibe-check
- Sidebar for kicking off and switching parallel tasks. Worktrees are created and cleaned up automatically. "Hopping between parallel tasks without losing context" is called the killer feature. Users like the git and terminal views (elpakal, HN). History and config are shared with the CLI and IDE extension. Cloud-to-local handoff is "genuinely cool".
- Dan Shipper moved from 80/20 to 50/50 Claude Code/Codex usage after adopting it.

**Complaints**
- **Lag/jank that scales with UI content.** Users report "10-15 FPS at best", "extremely jerky" scrolling, and that "lag seems to be directly proportional to how much UI is going on" (long conversations, expanded Projects, large file trees). The app uses about 1.3 GB at rest. https://community.openai.com/t/the-new-codex-app-ui-redesign-is-insanely-laggy/1401335 . UI lag also appears when working with many files, with low CPU/RAM, which points at rendering (https://community.openai.com/t/codex-becomes-extremely-slow-and-causes-severe-ui-lag-when-working-with-many-files/1376629). "Freezes/stutters on Windows 11 Pro despite sufficient system resources" (#20214, 87r/114c). "stutters on every single chat" (timpera, HN). "can't get codex app ... to work without hanging on even a moderately sized chat" (written-beyond, HN).
- **Resource bloat.** "8GB of RAM usage for Codex App is clown-level ridiculous" (behnamoh, HN 46859054). Bundles headless LibreOffice, about 3 GB install, "Somebody ship their monorepo verbatim?" (HN 49527396). GPU spikes from a "tiny useless animation" while thinking (#16857, 140r). macOS `syspolicyd`/`trustd` CPU and memory runaway (#25719, 454r).
- **Platform gaps.** Linux (#11023, 1463r, the most-reacted app issue), Intel Mac (#10410, 376r), standalone Windows installer (#13993, 270r), WSL worktrees written to /mnt/c (#13762).
- **Remote.** Remote development (#10450, 879r), remote control (#9224, 544r), cross-device sync (#21803).
- **Removed affordances.** Context/token usage indicator removed (#23794, 253r/172c). Branch selection removed (#49532, "Put the Branch selection BACK", 101r). "Copy as Markdown" removed (#25201). Pets that can't be disabled (#34349, 88r). Long pastes auto-converted to .txt attachments (#25144, 88r).
- **Missing basics.** Manual /compact (#11325, 158r), delete threads (#13018, 112r), message editing (#11086, 85r), auto-resume after the 5 h limit resets (#28931, 86r), custom model providers (#10867), configurable worktree location (#10599), multi-repo parent workspaces (#26338), multiple terminals (#11427), adjustable chat width (#16669), moving projects without breaking thread references (#11022), a commit+push button (#47511). Users say Codex "lacks simple controls found in Claude Code Desktop, such as /reset" (https://community.openai.com/t/is-codex-falling-behind-claude-code-desktop/1390411).
- **Reliability.** "Awaiting approval" prompt stuck and cannot be approved (#10760). Editing a queued follow-up errors (#44781, #45019). Users complain about roadmap opacity and that "feature requests seem ignored". Red/green diff colors are hard for colorblind users (dantiberian, HN).
- **Trust.** "OpenAI seems to be silently re-enabling model training on Codex chats" (HN 50352757, 536 pts).

### Claude Code desktop (Electron; redesigned Apr 2026 for parallel sessions)
**Praised**: parallel sessions in one window, worktree isolation by default, multi-repo sessions, an integrated terminal, a file editor, a rebuilt diff viewer for large changesets, side chats, Routines, PR controls ("keep the loop from agent output to review tight"), and the iOS simulator. https://claude.com/blog/claude-code-desktop-redesign , https://verygood.ventures/blog/claude-code-desktop-hands-on-review/ . One HN commenter calls it "modern Claude Code desktop, their old versions were bad".

**Complaints**
- **Long-session failure modes.** The new UI does not work with long chats of about 3k messages (claudeissues 49069). 18+ s input lag from a React render loop (31643). New messages hang in long sessions (58992). A 121 MB transcript hangs the app on Windows because inlined images are stored twice (85302). The app climbs to 4.5-5 GB RSS over 24 h, closed as not planned (80056). Windows UI lag and mouse stutter regression (#26302). The desktop app is slower than the VS Code extension because of MCP tool definitions (33759).
- **Bloat.** A 1.8 GB Hyper-V VM spawns on every launch even for chat (HN 48479452, 434 pts; #29045). A 10 GB Cowork VM bundle "you cannot remove" (#22543, 281r). Users want to disable CoworkVMService (#57371).
- **Top requests.** Multiple accounts/profiles (#18435, **1462r**), Linux build (#65697, 655r; HN 48434436, 538 pts), multi-window (#30154, 304r), CLI/desktop history sync (#28791, 192r), skills sync (#20697), Enter=newline / Ctrl+Enter=submit option (#89673, 167r), remote control (#29006), WSL execution (#12506, #49933), font size (#48237), usage stats panel brought back (#102264, 110r), status bar (#41456), custom themes (#79305), keyboard shortcuts to switch tabs (#18818), delete sessions (#13514), diff against branches other than main (#23626, 144r), option to disable auto-worktree for linked repos (#21236).
- The app inherits terminal env vars (API keys, base URLs) and fails with cryptic 400s (Product Hunt). A window stuck always-on-top on Windows (#85891, 292r). Merge conflicts between sessions are not surfaced.

### Conductor (Mac app, Claude Code + Codex, local worktrees)
**Praised**: clean UI and polish ("exactly what I needed"; "my favorite agentic Claude Code interface"). It reuses your existing Claude login. The workspace, diff, PR, merge and archive loop is tight. "nice clean simple extension" of Claude Code (simonbw). https://news.ycombinator.com/item?id=44594584 . The changelog claims a ground-up rebuild: "twice as fast", 50% faster tab and workspace switching, 150 MB smaller. https://www.conductor.build/changelog
**Complaints**: at launch it cloned from GitHub instead of using the existing checkout and required broad OAuth scopes ("Why not local git support?"; GH Enterprise unsupported). Worktrees skip untracked `.env*` files. "lost the feel of Claude Code's output and keybindings ... I just don't feel as joyful" (aantix). Mac-only. "the text rendering in Conductor always drove me nuts" (collin128, Superset HN). "rolled an entire UI when the terminal UI is good enough" (FleetCode HN). Human review is the bottleneck (oc1, petesergeant).
**Requested**: a dashboard of sessions waiting for confirmation, switching plan/execute mid-chat, queued and interrupting messages, a configurable base branch, custom "Open in..." targets, SSH remotes, multi-repo tasks, submodules, model routing/token budgets, brownfield setup scripts.

### Vibe Kanban (BloopAI; sunset 2026, now community-maintained)
**Praised**: "same increase in productivity ... as when I first used Cursor" (lharries), "slick", "game changer". It supports many CLIs. https://news.ycombinator.com/item?id=44533004
**Complaints**: analytics were on by default and collected emails and GitHub usernames, with GitHub auth granting "unlimited private access" ("hard NO"). The maintainer fixed this to opt-in within hours. The review bottleneck: "if we can review 10 PRs a day and AI writes one of them, we now have to review 11". Parallel cards "clobber each other". "~50% of the columns seem pretty redundant" (the maintainer). Kanban assumes independent tasks. **Redesign backlash**: "Bring back old UI" (#2687, 33r), "ALL old tasks and PROJECTS are gone" after upgrade, the board moved to the cloud and needs login ("Don't force users to log in just to access the core features"; #2952). A cross-project view was mixed in. Local runs slow after about 4 concurrent tasks.
**Requested**: self-hosted GitLab (#1697), configurable worktree cleanup (#765), `.worktreeinclude` (#1947), GitHub issues import (#1677), task dependencies (#1700), arbitrary ACP clients (#2365), multi-repo (#705), a master view across projects (#1106), keyboard shortcuts.

### Superset (superset.sh; Electron, terminal-first, worktrees)
**Praised**: it runs the native Claude/Codex TUIs "without any of the bloat" (cpan22). "feels so light compared to my vscode" (bicepjai). One user runs 40-50 sessions across repos. Worktree setup takes about 2 s. Notifications and cloud workspaces beat Conductor. https://news.ycombinator.com/item?id=48236770 , https://news.ycombinator.com/item?id=46368739
**Complaints**: "vibe coded electron app, 2GB!", freezing and glitches (desireco42). Character rendering breaks in long sessions and on 4K. xterm.js "can't handle when the terminals get large". A login wall. It downloaded its own OpenCode instead of using the installed one. Mac-first. Remote typing lag ("use mosh"). Paywalled Linear integration. "Most of these tools don't make working with Git merges or conflicts to main simpler" (sathish316). Worktrees don't isolate DBs and services.
**Requested**: per-worktree port allocation and Docker services with unique URLs, automatic conflict detection, BYO sandbox/SSH VMs, plan mode combined with skipped permissions, an in-session scratchpad (`/btw`), ACP, Discord/Slack.

### Sculptor (Imbue; containers per agent)
**Praised**: "cooking dinner and blasting out features". Claude can "go rogue safely inside a container". Task parallelism plus history. Bidirectional sync of uncommitted changes ("pairing"). Snapshots after each turn. https://news.ycombinator.com/item?id=45427697
**Complaints**: "sculptor_backend seems to consume a lot of CPU and memory when just idling". Crashes on Linux/Wayland Chrome. OrbStack not detected. A confusing mental model ("what is a container/pairing?"). Worry about many Postgres instances on a laptop. Claude-only at launch. No base-URL configuration. Suggestion to move from Electron to Tauri.
**Requested**: OpenCode, Codex, Gemini, cheaper models (Qwen/GLM/Kimi), web/mobile access, SSH remote, Intel Mac.

### Opcode (ex-Claudia; Tauri)
**Praised**: it coexists with normal terminal Claude Code. Tauri is lighter.
**Complaints** (HN 44933255): sluggish UI and slow scrolling. Chat sessions jump to earlier points or lose messages. Code changes are hidden behind an "AI Summary". Binaries fail on old glibc. The name implies it is official. "the Claude Code cli [is] a better experience than this" (yen223). "Total Cost": subscription or API-equivalent? It stagnated (220+ open issues).
**Requested**: Plan mode (#105, 50r), SSH remote (#163), claude-code-router/custom models (#84), non-Claude CLIs (#66), Windows build, web app, a way to stop autoscroll (#212), 4K/HiDPI scaling (#86).

### Crystal (stravu; deprecated Feb 2026 for Nimbalyst)
**Praised**: it works with existing checkouts and local branches. "best of these tools" (redhale). It does one thing well without forcing config.
**Complaints/requests**: "Is this app secretly phoning home?" (#95). Permission bypass forced (#178, "Allow running without --dangerously-ignore-permissions"). Escape loses your prompt (#183). Auto-resume after the Max limit (#18). Codex support (#177). Remote and mobile server mode (#26, #89). Notification settings don't persist (#58, #109).
**Nimbalyst** (vendor blog, biased): it argues that the remaining pain after worktrees is that session rows hide the work, attention alerts arrive without context, there is no cross-session review of coupled changes, context doesn't transfer between agents or vendors, and scheduled agents lack workspace context. https://dev.to/stravukarl/what-actually-breaks-when-you-run-5-claude-code-agents-in-parallel-1lbd

### Cursor Agents Window (2.0 Oct 2025, Cursor 3 "Glass" Apr 2026)
**Praised**: some like having both views, and best-of-N parallel agents.
**Complaints**: being forced into the agent view by default ("why the update is automatically setting people on the Agents view"; "2.0 is steering me away from my code ... I lose my sense of ownership"). https://forum.cursor.com/t/2-0-a-step-in-the-wrong-direction/139648 . Cursor 3 gaps: no extensions/LSP/IntelliSense, a "simplified diff view" with no per-hunk accept/reject ("a must for people with money on the line"), whole files shown as new, infinite-scroll changes, no global diff toggle, no line wrap in diffs, file links open new tabs, broken shortcuts, light/dark only. https://forum.cursor.com/t/cursor-3-0-agentic-ide-huge-potential-but-blocked-by-key-usability-gaps/156803 , https://forum.cursor.com/t/agents-window-is-not-good/157226 . The new `/worktree` flow is agent-driven and "takes 10-20 seconds to do what I've done before with a single click", which makes it "unusable" (https://forum.cursor.com/t/new-worktree-workflow-seems-like-a-downgrade/157556). Agents write to the root repo instead of the worktree. Worktrees are invisible in Source Control. Users can't @-reference another agent's results. **Memory**: 98 GB aggregate with 6 background agents on a 16 GB Mac. Staff advise limiting to 2-3 agents and reloading (https://forum.cursor.com/t/title-cursor-reaches-98gb-memory-with-6-parallel-background-agents-macos-memory-pressure-system-freeze-16gb-mac/168061). Thread titles show the hostility: "Agents Window is hostile UX", "Please stop pushing the Agent Window so aggressively", "Trapped in Cursor Agents Window?".

### Zed agent panel (native Rust; ACP external agents; Terminal Threads)
**Praised**: native performance. ACP lets you bring your own agent (Claude, Codex, Gemini). Terminal Threads let you run `claude`/`codex`/`amp` TUIs as managed threads with a sidebar, keyboard navigation and notifications. https://zed.dev/blog/terminal-threads
**Complaints**: Claude Code over ACP loses CLI features (no reasoning-effort toggle, no slash commands; discussion #52293). Anthropic moving Agent SDK subscription usage to separate credits made ACP Claude "much more expensive", which forced the terminal-threads route. Checkpoint restore is "irreversibly destructive" (#28676). The panel doesn't show modified files (#49600). The Git panel goes stale when an agent in another window edits files (#60882). Users want vim mode in the panel (#30081) and terminal/diagnostics as context (#31351).

### Warp (terminal-turned-ADE)
**Praised**: first-class hosting of Claude Code/Codex/Gemini/OpenCode in panes, and the terminal quality. https://www.g2.com/sellers/warp-4ef36c2a-b797-43bd-8e00-6951126a552e
**Complaints**: forced login and onboarding surveys. Opaque request counting ("Until Warp provides a transparent and detailed explanation of how requests are counted..."). ## 2. Cross-cutting themes, ranked by frequency and intensity

1. **UI performance degrades with session length and count (lag, memory, Electron bloat).** This comes up for almost every tool: Codex (1.3-8 GB, 10-15 FPS, 3 GB install), Claude desktop (3k-message wall, 18 s input lag, 5 GB leak, 1.8 GB VM), Cursor (98 GB with 6 agents), Superset (2 GB, glyph corruption), Emdash (78 tasks crawl), Sculptor (idle CPU), Opcode (slow scroll), T3 (26 GB DB, 12-50 s thread switches), OpenCode GUI vs TUI. The root causes repeat: whole-history render with no virtualization, inlined base64 images, storing every streaming snapshot, unbounded per-agent processes, and decorative animations.
2. **Platform reach: Linux, Windows/WSL, Intel Mac.** These are the top-reacted issues on Codex (#11023 1463r, #10410 376r, #13993 270r), Claude (#65697 655r), and T3 (#192 145r). Nearly every Show HN thread gets "Why Mac only?".
3. **Remote, SSH, and mobile control of agents running elsewhere.** Codex #10450 (879r) and #9224 (544r), Claude #29006, Opcode #163, Crystal #26/#89, Emdash #901, Sculptor, Conductor. T3's remote is its most-praised differentiator. Omnara and Happy exist only for this.
4. **Multi-provider / bring-your-own agent and models.** T3's top 4 requests are new providers (130-198r). Every launch thread asks for OpenCode, Codex, Gemini or Copilot. Codex #10867 asks for custom providers, Opcode #84 for a router.
5. **Review is the real bottleneck, and diff UX quality decides the tool.** HN threads for Vibe Kanban, Superset, Conductor and FleetCode all raise "review time becomes the bottleneck". Users specifically want per-hunk accept/reject (Cursor), diff since last turn (Emdash #1635), diff against any base branch (Claude #23626), large-diff performance, colorblind palettes, line wrap, combined review across coupled sessions, and LSP/IntelliSense inside review to catch hallucinated APIs.
6. **Worktrees are necessary but not sufficient: environment isolation.** Users hit missing `.env`/untracked files, port collisions, shared DBs/Redis, migrations, submodules, disk blow-up (500 GB), cleanup, configurable location (Codex #10599), WSL paths, and being forced to clone instead of using the existing checkout. They ask for setup/teardown scripts, `.worktreeinclude`, per-worktree ports, Docker services and URLs.
7. **Usage, cost, context and rate-limit visibility, and wrapper efficiency.** The Codex indicator removal (#23794, 253r/172c) got a large backlash. Related: Claude desktop usage panel (#102264), status bar (#41456), T3 #228/#9352, Codex reset dates (#28161), Opcode "Total Cost", Warp opaque counting. A wrapper that burns 3-5x the quota (T3 #7338) or runs slower than the native agent (T3 #695) loses users.
8. **Attention routing: notifications and an approvals inbox.** T3 #780 (64r). Conductor users want a "dashboard showing which sessions are waiting for confirmation". Emdash #531 wants a distinct approval icon. Codex has a stuck "Awaiting approval" bug (#10760). Superset's notifications are praised. Nimbalyst points out that alerts without context force a context switch. Antigravity users were angry when the Inbox was removed.
9. **Forced redesigns, removed features, and default-view hijacking.** Cursor 2.0/3, the Codex redesign (lag plus removed branch picker, token indicator and copy-as-markdown, undeletable pets), the Vibe Kanban new UI (lost projects, cloud login), Antigravity inbox removal, T3 removing the legacy sidebar and hiding the context indicator. Users want a stable UI, opt-in changes, and release notes (Codex #10859).
10. **Privacy, telemetry, auth scope, forced login.** Vibe Kanban analytics, Conductor's GitHub OAuth scope, Crystal "phoning home", T3 telemetry (#4123), the Vibe Kanban and Superset login walls, Warp's forced login, Omnara's lack of E2EE, Codex training on chats.
11. **Session lifecycle: resume, search, delete, fork, edit, sync.** Codex delete (#13018) and edit (#11086). Claude delete (#13514) and CLI/desktop sync (#28791). T3 branching (#1404), context lost on idle (#2256), Codex project moves (#11022). Users also want to find past work by content.
12. **Steering while a run is active: steer vs queue, plan mode.** T3 #231 (77r), Conductor (buremba), Opcode plan mode (#105, 50r), Superset plan mode with permissions skipped, Codex queued-follow-up bugs.
13. **Preserve the native agent's power: slash commands, keybindings, TUI fidelity.** "lost the feel of Claude Code's output and keybindings" (Conductor). Zed ACP lacks slash commands and effort control. T3 #2491. Opcode: "thin layer that preserves ... plan mode and sub-agents". Superset and Zed Terminal Threads are loved for embedding the real TUI.
14. **Multi-account and auth switching.** Claude #18435 (1462r, one of the most-reacted desktop issues), CLI #30031, T3 Codex account-switch locks (#30630).
15. **Keyboard-first and input ergonomics.** Claude: Enter/Ctrl+Enter (#89673, 167r), tab-switch shortcuts (#18818). Zed vim mode. Emdash Cmd-K. Cursor shortcuts broken. Codex quick-chat hotkey. Vibe Kanban shortcuts. Crystal: Escape loses your prompt.
16. **Multi-repo workspaces.** Codex #26338, T3 #1453, Vibe Kanban #705, Conductor (frontend+backend). Claude desktop is praised for spanning repos.
17. **Auto-resume after rate-limit reset.** Codex #28931 (86r), Crystal #18, T3 #16815.
18. **Subagent and parallel visibility.** T3 #538 (nested threads). Cursor: "what are parallel agents doing?". Users can't @-reference another agent's output. Board-level "who's on which branch, blocked, ready to merge".
19. **Integrations beyond GitHub.** GitLab (VK #1697, Emdash, Superset), GitHub Enterprise (Conductor), Linear (paywalled in Superset), Jira/issues import.
20. **Security defaults.** T3 defaulting to Full access. Crystal forcing `--dangerously-skip-permissions`. Users want OS-level sandboxing rather than "trust in the LLM" (alphazard, Claudia HN). Containers are praised (Sculptor), but VMs must not cost 1.8-10 GB when unused.

## 3. Prioritized feature and UX list for the "best orchestrator"

P0 = table stakes; missing any of these is cited as a reason to leave. P1 = strong differentiators users explicitly ask for. P2 = polish and moat.

### P0
1. **Bounded-cost rendering and storage for long and many sessions.** Virtualized transcript (render only the viewport), collapsed tool output loaded lazily, images stored once by hash off the transcript, streaming deltas compacted into one final record, history paged from disk, a per-session memory cap, and no idle animations. Target: a 3k-message thread scrolls at 60 fps, the idle app uses under 300 MB, and 20 live sessions don't degrade. *Why*: theme 1 is the top complaint everywhere (Codex 10-15 FPS; Claude 3k-message wall; T3 26 GB DB and 2.2 GB/day snapshots; Cursor 98 GB; Superset 2 GB). Consider a native or Tauri shell, or at least a disciplined Electron renderer. Users reward "40 MB rather than over 400" and "without any of the bloat".
2. **Parallel sessions with one-click worktrees, including environment bootstrap.** Use the existing checkout (no forced clone or OAuth). Provide setup/teardown/run scripts, `.worktreeinclude` for `.env` and untracked files, automatic unique port allocation per worktree with env injection, optional per-worktree Docker compose services and local URL, a configurable worktree location, a disk-usage meter, auto-cleanup on merge/archive, and support for submodules and WSL-native paths. *Why*: theme 6. Requests come from Conductor (pjm331, clbrmbr), Superset (jpalomaki, nullbio, 101008), FleetCode (osener), VK #765/#1947, Codex #10599/#13762, and T3 (500 GB).
3. **A first-class diff review flow.** Show per-turn and cumulative diffs, diff vs any base branch, and per-file and per-hunk accept/reject/revert. Add inline comments that go back to the agent as a follow-up, split/unified views, line wrap, a colorblind-safe palette, and fast rendering on 800-file changesets (no per-file git storms). Add LSP-backed go-to-definition and type errors in review, plus one-click commit/push/PR and local merge without a PR. *Why*: theme 5. Every's "standout feature"; Cursor's "a must for people with money on the line"; Emdash #1635/#1269; Claude #23626; T3 #40182.
4. **An attention inbox with OS notifications.** One queue of "needs approval / asked a question / finished / failed / hit limit" across all sessions. Each item shows the question with enough context to answer inline (approve, deny, reply) without opening the transcript. Add native notifications and a dock/tray badge, and give approvals a distinct icon from "working". *Why*: theme 8. T3 #780; Conductor HN "dashboard showing which sessions are waiting"; Emdash #531; Nimbalyst on context-free alerts; Codex stuck approvals #10760; the Antigravity inbox backlash.

T3 #7338 (3-5x usage) and #695 (slower than native); Zed ACP losing slash commands and getting repriced; "lost the feel of Claude Code" (Conductor); the top T3 requests are all providers.

No training on transcripts. Works offline. *Why*: theme 10. The Vibe Kanban HN privacy uproar and #2952, Conductor OAuth, Crystal #95, T3 #4123, the Superset and Warp login walls.

## 4. Anti-patterns to avoid

1. **Rendering or loading the full history eagerly.** This is the root of Codex, Claude desktop and Opcode lag. Never load the whole transcript into the DOM or memory.
2. **Storing every streaming snapshot or base64 image in the event log forever.** T3 hit 2.2 GB/day and 26 GB DBs, and Claude desktop had 121 MB transcripts with duplicated images. Compact deltas, deduplicate blobs, and make delete actually delete.
3. **Shelling out to git on every UI tick.** T3 Windows ran about 1,650 git processes to view 272 files and 15-17 processes per thread per poll. Cache, batch, and watch the filesystem.
4. **Unbounded per-agent processes and memory.** Cursor reached 98 GB. Staff advice to "limit to 2-3 agents and reload" is a product failure.
5. **Hidden always-on heavyweight subsystems.** Examples: a 1.8 GB VM at launch, a 10 GB bundle you cannot remove, bundled LibreOffice, a GPU-burning spinner, and pets you can't disable. Make heavy features lazy, opt-in and removable.
6. **Forcing a new default view or workflow, or removing working features in a redesign.** Cursor Agents Window, the Codex redesign (branch picker and token indicator removed), the Vibe Kanban new UI (lost projects), and the Antigravity inbox all drew backlash. Keep classic modes, migrate data losslessly, publish release notes.
7. **Agent-mediated versions of deterministic actions.** Cursor's `/worktree` asks the LLM to do what a button did, costing "10-20 seconds", tokens and reliability. Git, worktree, commit and merge should be deterministic UI actions.
8. **Wrapping the agent in a way that costs more quota or speed than the native tool,** or strips its slash commands and keybindings (T3 #7338/#695, Zed ACP, the Conductor "joy" comment).
9. **Login walls, cloud-only state for single users, telemetry on by default, broad OAuth scopes** (Vibe Kanban, Superset, Warp, Conductor launch, Crystal, T3).
10. **Unsafe defaults** such as Full access or forced `--dangerously-skip-permissions`.
11. **Mac-only launches** without a credible Windows/Linux timeline.
12. **Kanban as the primary metaphor.** It assumes independent tasks, and its columns go redundant when the agent does the work. Use a status board and inbox, not ceremony.
13. **Session-as-a-row with context-free alerts.** Users have to open the transcript just to find out what is being asked.
14. **Optimizing for "launch 10 agents" over review throughput.** HN skeptics repeatedly point out that you convert "typing time" into "reading time", which is usually worse. Invest in review, conflict detection and verification, not just fan-out.
15. **Opaque or silently changed metering, and hiding usage indicators** (Warp request counting, Codex #23794, T3 #9352).
16. **Naming or branding that implies an official vendor product** (Claudia), or demos and marketing copy that hide the workflow (Superset and Claudia HN threads).
